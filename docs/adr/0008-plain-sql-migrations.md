# ADR-8: Plain SQL migrations with a small runner

**Status:** Accepted (M0)

ADR-1 to ADR-7 live in section 16 of [design.md](../design.md). New decisions go in this folder and continue that numbering.

## Context

The schema needs versioned migrations from M0. The store layer uses hand-written SQL with bound parameters (ADR-1) and has no ORM. The schema leans on Postgres features: pgvector, generated `tsvector` columns, partial unique indexes with `NULLS NOT DISTINCT`.

## Decision

Migrations are numbered `.sql` files in `src/verified_rag/store/migrations/`, applied by `verified_rag.store.migrate` (`vrag migrate`). Each runs once, in its own transaction, under an advisory lock, and is recorded in `schema_migrations` with a SHA-256 checksum. Editing an applied migration is an error; changes go in a new file. Migrations are forward-only.

## Consequences

- No SQLAlchemy or Alembic dependency, and the schema reads exactly as Postgres runs it.
- No autogenerated migrations and no down migrations. Rolling back means writing a new forward migration, or restoring a backup.
- If this becomes limiting (for example, many contributors or complex data migrations), switch to Alembic with raw-SQL revisions; the existing files can be imported as its first revision.
